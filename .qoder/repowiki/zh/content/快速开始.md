## 简介
本指南面向从零开始搭建个人技术博客的读者，基于 Hugo 静态站点生成器与 Blowfish 主题。你将完成环境准备、仓库克隆、子模块初始化、Git Hooks 启用、本地预览以及草稿预览等关键步骤，并附带常见问题的排查方法。

## 环境要求
- Hugo extended 版本：项目通过配置文件锁定 Hugo 版本，确保本地与 CI 一致。
- PowerShell 7+：用于运行仓库提供的脚本（如启用 Git Hooks、校验 Front Matter）。

说明：
- 项目 README 明确列出环境要求为 Hugo extended 与 PowerShell 7+。
- Hugo 核心配置中设置了默认语言、主题、相关构建行为等参数，这些参数会影响本地构建与预览体验。

## 克隆与初始化
目标：将博客仓库克隆到本地，并初始化依赖的主题子模块。

操作步骤：
1. 打开终端或 PowerShell。
2. 执行以下命令克隆仓库：
   - git clone https://github.com/ZUOXIANGE/zuoxiange.github.io.git
3. 进入项目目录：
   - cd zuoxiange.github.io
4. 初始化并更新 Git 子模块（主题）：
   - git submodule update --init --recursive

注意事项：
- 如果网络受限或 GitHub 访问不稳定，可考虑使用镜像源或代理；若仍失败，稍后重试或使用离线方式获取主题。
- 首次克隆必须执行子模块初始化，否则主题资源缺失会导致构建失败或样式异常。

## Git 子模块配置
作用：
- 主题以 Git 子模块形式引入，便于独立升级与维护，同时避免直接修改主题代码被覆盖。

当前配置：
- 子模块名称：themes/blowfish
- 路径：themes/blowfish
- 远程地址：https://github.com/nunocoracao/blowfish.git

建议：
- 不要直接修改 themes/blowfish 下的内容，如需定制请放在站点层（例如 layouts、assets/css/custom.css）。
- 升级主题时使用：
  - git submodule update --remote --merge

## 启用 Git Hooks
作用：
- 在提交前自动校验文章 Front Matter 必填字段（如 slug、description、categories、tags），未通过则阻止提交，保证内容质量与一致性。

启用步骤：
1. 在项目根目录执行：
   - pwsh -NoProfile -File scripts/setup-hooks.ps1
2. 脚本会设置 Git 钩子路径为 .githooks，并在控制台输出确认信息。

工作原理：
- setup-hooks.ps1 调用 git config core.hooksPath .githooks，使 Git 在执行 pre-commit 时读取 .githooks 下的脚本。
- .githooks/pre-commit 会调用 PowerShell 脚本 scripts/check-frontmatter.ps1 进行校验。

注意事项：
- 如果系统未安装 PowerShell 7+，请先安装后再执行该脚本。
- 若已存在其他 hooksPath 配置，执行脚本后会覆盖为 .githooks。

## 启动本地开发服务器
目标：在本地预览博客，支持热更新与草稿预览。

启动命令：
- hugo server

浏览器访问：
- http://localhost:1313/

草稿预览：
- hugo server -D

说明：
- hugo server 会在本地启动开发服务器，监听端口 1313，修改 Markdown 或模板文件后自动刷新页面。
- -D 参数允许预览草稿文章（draft = true），适合写作阶段预览。

Hugo 构建行为参考：
- 默认不构建草稿与未来文章，生产构建需显式开启相应选项。
- 站点默认语言为 zh-cn，主题为 blowfish，相关参数影响本地构建与预览效果。

## 常见问题与排错
问题一：无法找到 hugo 命令
- 现象：终端提示找不到 hugo 命令。
- 原因：未安装 Hugo 或未加入环境变量。
- 解决：
  - 安装 Hugo extended 版本，并确保 hugo 命令可用。
  - 检查 PATH 是否包含 Hugo 安装目录。

问题二：主题子模块未初始化导致构建失败
- 现象：构建时报主题缺失或样式异常。
- 原因：未执行 git submodule update --init --recursive。
- 解决：
  - 在项目根目录执行子模块初始化命令。
  - 若已初始化但主题损坏，可删除 themes/blowfish 后重新执行初始化。

问题三：Git Hooks 未生效
- 现象：提交前未触发 Front Matter 校验。
- 原因：未设置 core.hooksPath 或脚本未执行成功。
- 解决：
  - 执行 pwsh -NoProfile -File scripts/setup-hooks.ps1。
  - 确认 git config core.hooksPath 输出为 .githooks。
  - 检查 .githooks/pre-commit 是否存在且可执行。

问题四：PowerShell 脚本执行失败
- 现象：setup-hooks.ps1 报错或无输出。
- 原因：未安装 PowerShell 7+ 或执行策略限制。
- 解决：
  - 安装 PowerShell 7+。
  - 在当前会话临时放宽执行策略（谨慎操作）：Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass。
  - 再次执行脚本。

问题五：本地预览看不到草稿
- 现象：新建文章后本地预览不显示。
- 原因：草稿默认不构建。
- 解决：
  - 使用 hugo server -D 启动服务器预览草稿。
  - 或将文章的 draft 字段改为 false 后正常预览。

问题六：网络问题导致子模块拉取失败
- 现象：git submodule update 卡住或失败。
- 原因：GitHub 访问不稳定或代理配置问题。
- 解决：
  - 检查网络与代理设置。
  - 尝试更换 DNS 或使用镜像源。
  - 多次重试或稍后重试。
